# 第二章：阵等级、元素与功能目录

## 1. 等级机制

| 等级 | 数值 | 相对速度因子 | 相对产出因子 |
| --- | ---: | ---: | ---: |
| 不稳定 | 0 | 1.00 | 1.00 |
| 稳定 | 10 | 0.75 | 1.00 |
| 稳固 | 20 | 0.75 | 1.10 |
| 充盈 | 30 | 0.75 | 1.10 |
| 古朴 | 40 | 0.75 | 1.20 |
| 远古 | 50 | 0.75 | 1.20 |

速度和产出按跨越的等级逐级累乘。例如，不稳定配方放入稳固同功能阵时，时长乘以 `0.75 × 0.75`；产出乘以 `1.00 × 1.10`。最终加工时长至少为 1 tick。物品产出倍率的具体取整应以运行逻辑为准，不应仅按表格心算承诺结果。

高等级阵可以处理同一基础功能的低等级配方，低等级阵不能反向处理高等级配方。兼容判断依赖阵 ID 的等级前缀；无法识别等级的扩展 ID 会走保守兼容路径。

## 2. 功能自动展开

每个功能只声明一次“最低引入等级”，注册时会自动生成该等级及其后的所有阵类型。ID 形式为：

```text
magic_io:<等级前缀><功能名>_zhen
```

例如筛分从不稳定级引入，因此存在 `unstable_sieve_zhen`、`stable_sieve_zhen`，一直到 `primeval_sieve_zhen`。创造只在远古级引入，因此只有 `primeval_creative_zhen`。

## 4. 元素的实际作用

当前元素类型用于描述和分类阵功能。源码注册了土、水、风、火、木、冻、金、雷、秩序、空间、时间、混沌、描述、能量、灵魂、创造十六种元素。

**限制：**当前不能从元素名称推导出统一的物理规则。例如“火”并不会自动兼容所有熔炉配方，“金”也不会自动完成所有金属加工。真正可加工的内容由阵配方 JSON 决定。

## 5. 配方覆盖现状

资源目录提供 37 个阵配方文件：不稳定 4 个、稳定 8 个、稳固 8 个、充盈 8 个、古朴 8 个、远古 1 个。高等级自动展开出来的阵不一定拥有同等级专属配方，但仍可向下兼容同功能低等级配方。

这意味着“方块存在”不保证“存在该等级的新配方”。判断某个阵是否有内容时，应同时检查注册类型和 `data/*/recipe` 数据。
