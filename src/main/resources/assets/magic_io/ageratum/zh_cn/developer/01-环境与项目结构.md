# 第 01 章：开发环境与项目结构

## 1. 本章目标

本章以当前仓库为准，说明 MagicIO 的运行基线、Gradle 配置、源码目录、加载入口和服务端/客户端边界。阅读后应能判断一项功能应放在哪个包、在哪条事件总线上初始化，以及资源应进入手写目录还是生成目录。

## 2. 当前技术基线

| 项目 | 当前值 | 源码依据 |
|---|---:|---|
| Minecraft | 26.1.2 | `gradle.properties` 的 `minecraft_version` |
| NeoForge | 26.1.2.41-beta | `gradle.properties` 的 `neo_version` |
| Java | 25 | `build.gradle` 的 Java Toolchain |
| Mod ID | `magic_io` | `gradle.properties` 与 `MagicIO.MOD_ID` |
| Java 包 | `cn.yhzcake.magicio` | `mod_group_id` 与源码包路径 |
| 构建插件 | NeoForge ModDevGradle 2.0.141 | `build.gradle` |

项目要求 Java 25，不应只修改 IDE 的项目 SDK；Gradle Toolchain 才是编译任务采用的真实版本。模组版本、名称、许可证和 Minecraft/NeoForge 版本均由 `gradle.properties` 注入模板，而不是直接维护最终的 `neoforge.mods.toml`。

## 3. Gradle 与运行配置

`build.gradle` 应按以下层次理解：

1. `java-library`、`maven-publish` 和 `net.neoforged.moddev` 提供 Java 编译、发布以及 NeoForge 开发运行配置。
2. `sourceSets.main.resources` 把 `src/generated/resources` 合并进主资源集，因此数据生成结果会随模组一起打包。
3. `neoForge.runs` 定义 `client`、`server`、`gameTestServer` 和 `data` 四类运行目标。
4. `data` 运行把生成物写入 `src/generated/resources`，并把 `src/main/resources` 作为已有资源输入。
5. `generateModMetadata` 展开 `src/main/templates`，输出到构建目录；模板文件才是元数据源文件。
6. JEI 与 Jade 当前使用 `compileOnly`，源码可以编译兼容模块，但它们不是开发运行时必然存在的依赖。

### 3.1 资源覆盖风险

主资源和生成资源会合并。若两个目录出现相同资源位置，维护者必须明确哪个文件是权威来源。当前大量阵物品模型位于 `src/generated/resources/assets/magic_io`，而语言、方块状态、纹理、配方及战利品表主要位于 `src/main/resources`。

### 3.2 可选兼容模块

`compat/jei` 和 `compat/jade` 依赖编译期 API。它们分别通过 `META-INF/services` 声明插件入口。开发时不能据此假定 JEI/Jade 一定在运行环境中；公共核心逻辑也不应依赖兼容插件完成初始化。

## 5. 两条事件总线

MagicIO 同时使用两类事件总线，混淆它们会导致监听器永远不执行。

### 5.1 Mod 事件总线

构造器参数 `IEventBus modEventBus` 负责注册生命周期内容：

- `DeferredRegister`：元素、IO 类型、阵类型、方块、物品、方块实体、创造模式页和配方类型。
- `FMLCommonSetupEvent`：公共初始化。
- `RegisterCapabilitiesEvent`：方块 Capability 提供者。
- 网络载荷注册事件。
- `BuildCreativeModeTabContentsEvent` 等模组生命周期事件。

### 5.2 NeoForge 游戏事件总线

`NeoForge.EVENT_BUS.register(this)` 注册运行期游戏事件，例如玩家交互、服务器启动和服务端资源重载。阵配方的资源重载与服务器生命周期属于这一侧，而不是注册表生命周期。

## 6. 公共端与客户端边界

`MagicIO` 是公共入口，类加载必须对专用服务端安全。`MagicIOClient` 使用 `@EventBusSubscriber(..., value = Dist.CLIENT)`，只负责：

- 注册 NeoForge 配置界面；
- 注册 `ZhenBusBlockEntityRenderer`；
- 承担客户端生命周期逻辑。

配方以服务端为权威：服务端加载阵配方后，通过 `ZhenRecipeSyncPayload` 同步客户端；客户端不预加载配方。这样可避免客户端注册表尚未稳定时创建错误缓存，也保证联机时客户端展示与服务器规则一致。

## 7. 初始化顺序

当前 `MagicIO` 构造器体现了明确依赖链：

1. 注册数据组件。
2. 把 `ElementType`、`ZhenType`、`IOType` 的静态事件订阅类挂到 Mod 总线，以创建自定义 Registry。
3. 注册元素和 IO 类型条目。
4. 注册阵类型及配方系统。
5. 根据阵类型的 DeferredRegister 条目生成阵方块，再生成对应 BlockItem。
6. 把方块、物品、阵总线方块/方块实体及普通阵方块实体挂到事件总线。
7. 注册公共初始化、网络、创造模式页和 Capability 监听器。
8. 注册游戏事件与 COMMON 配置。

关键点是“声明”与“取值”分离。`Supplier#get` 或 `DeferredHolder#get` 只能在对应注册表可用的时机调用。因此 `ZhenFunction` 把 `ElementTypes.*.get()`、`ModIOTypes.*.get()` 和槽位分区构造放进注册供应器，而不是静态初始化阶段立即求值。

## 8. 开发定位路线

新增功能前按以下顺序定位：

1. 判断它是注册对象、运行期对象、资源数据还是客户端表现。
2. 注册对象进入对应 `DeferredRegister`；运行期对象由方块实体或处理器持有。
3. 跨物品/流体/能量的处理优先进入 `io` 和 `item/crafting`，不要在方块交互中重复实现。
4. 独立方块形态阅读 `ZhenBlock` 与 `AbstractZhenBlockEntity`；总线面形态阅读 `SideProcessor` 与 `ZhenBusBlockEntity`。
5. 客户端显示放入 `MagicIOClient`、renderer 或 compat 包，不让公共入口引用客户端类。

## 9. 调试检查表

- 注册失败：检查监听器是否挂在 Mod 总线，以及自定义 Registry 是否先于 DeferredRegister 条目创建。
- 服务器崩溃：检查公共类是否直接引用 `net.minecraft.client` 类型。
- 资源不存在：检查命名空间是否为 `magic_io`，并确认资源位于主资源或生成资源的正确相对路径。
- 配方客户端缺失：先检查服务端重载和网络同步，不要在客户端重复加载资源。
- 方块实体不创建：检查 `BlockEntityType` 的合法方块集合是否包含目标方块。
- Capability 仍为旧对象：修改处理器后必须调用 `Level#invalidateCapabilities`。

## 10. 小结

MagicIO 是 NeoForge 26.1.2、Java 25 项目。核心结构以自定义注册表描述“类型”，以方块实体或面处理器保存“实例状态”，以统一配方处理器执行逻辑，以服务端资源重载和网络同步维护数据权威。后续四章分别展开注册体系、阵扩展、IO/Capability 和阵总线。
