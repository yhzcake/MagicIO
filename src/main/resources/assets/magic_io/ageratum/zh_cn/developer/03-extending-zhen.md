# 第 03 章：阵扩展

## 1. 核心模型

MagicIO 把“阵功能”和“阵等级”正交拆分：`ZhenFunction` 描述功能族，`ZhenLevel` 描述等级，二者展开成最终注册对象 `ZhenType`。同一个 `ZhenType` 既可驱动独立 `ZhenBlockEntity`，也可被阵总线包装为一个 `SideProcessor`。

```text
ZhenFunction + ZhenLevel
          ↓ register
       ZhenType
       ↙      ↘
独立阵方块实体   阵总线面处理器
          ↘   ↙
       RecipeProcessor
```

## 2. ZhenLevel：等级与配方倍率

当前等级依次为不稳定 0、稳定 10、稳固 20、充盈 30、远古 40、太初 50。每级包含 ID 前缀、等级值、相对前一级的速度倍率和产出倍率。

`totalSpeedMultiplier` 与 `totalOutputMultiplier` 会沿等级序列累计相对倍率。例如某功能从 10 级引入，计算 10 到 30 的倍率时会累计 20、30 两级因子。新增等级时必须同时考虑：

- `ALL` 中的顺序；
- ID 前缀和语言键；
- 配方展开逻辑；
- 模型和物品资源；
- 已有存档 ID 的稳定性。

## 3. ZhenFunction：功能族声明

`ZhenFunction` 保存七类信息：基础名、元素供应器、首次出现等级、槽位分区供应器、面访问规则、可选 TickFactory、可选流体容量。`register` 遍历所有等级，跳过低于引入等级的项，并生成：

```text
<等级前缀><基础名>_zhen
```

例如 `sieve` 从等级 0 引入，会产生 `unstable_sieve_zhen` 到 `primeval_sieve_zhen`；从等级 30 引入的功能只产生后三个等级。

现有便捷工厂包括：

- `simpleItem`：物品输入槽 0、输出槽 1，无自定义 tick；
- `simpleItemWithTick`：相同槽位并附带 tick；
- `tickOnly`：无存储，适用于传送门等世界行为；
- `fluidItem`：物品输入/输出并增加一个流体输出槽和容量。

## 4. ZhenType：运行定义

最终 `ZhenType` 是不可变类型对象，包含：

- 元素类型和完整类型字符串；
- `SlotPartition`；
- 等级数值；
- 可选 tick 工厂；
- 可选流体、能量容量；
- `Direction → IOType → 槽位索引集合` 的面访问表；
- 虚拟端口到槽位区域名的映射。

构造时，面访问配置仍使用区域名；`buildFaceAccess` 根据 `SlotPartition` 把区域名解析为整数槽位。这样业务声明不依赖具体槽号，但区域名必须能在分区中找到。不存在的区域会得到空槽集合，不会自动报错，因此扩展时应主动核对。

## 5. 槽位分区

`SlotPartition` 使用 `SlotZone → IOType → Set<Integer>` 表示槽位语义。标准区域包括物品输入/输出、流体输入/输出、能量输入/输出及世界掉落输出。

注意槽号按每种 IO 组件自己的存储解释。物品槽 0 和流体槽 0 可以同时存在，它们由不同 `IOType` 区分。槽位索引应从 0 连续排列；`getTotalSlots(IOType)` 返回唯一索引数量，若只声明槽 3 而没有 0 至 2，创建长度为 1 的容器后访问槽 3 会越界。

## 6. 独立阵生命周期

`ZhenBlock` 创建统一的 `ZhenBlockEntity`，服务端 ticker 调用 `AbstractZhenBlockEntity.serverTick`。普通阵的工作路径是：

1. 方块实体根据方块 ID 解析 `ZhenType`。
2. 按分区创建物品、流体和能量 IO 组件。
3. IO 变化回调调用 `setChanged`，并把配方状态标记为输入已变化。
4. 服务端 tick 调用统一 `RecipeProcessor.processTick`。
5. 无当前配方时按间隔检查，避免每 tick 扫描全部配方。
6. 匹配后推进处理时间，完成时模拟并提交输入消耗及输出插入。
7. 必要时同步方块实体状态。

破坏 `ZhenBlock` 时，容器物品会掉落并清空。流体、能量或自定义组件若要求回收，需要在对应生命周期中明确设计，不能默认由 `Container` 处理。

## 7. 配方驱动与自定义 Tick

标准加工阵应优先使用阵配方和 `RecipeProcessor`，以共享输入匹配、进度、倍率、产出、重载和网络同步。`TickFactory` 更适合不完全是配方加工的世界行为，例如传送门。

自定义 tick 必须遵循：

- 仅在服务端改变世界和持久状态；
- 使用传入的 `Level`、`BlockPos`、`BlockState` 和方块实体，不长期缓存失效世界对象；
- 修改 IO 后触发组件变更回调；
- 控制扫描范围和执行频率，避免每 tick 大范围遍历；
- 方块实体参数带可空语义时必须处理总线等复用场景。

## 8. 新增标准阵功能的步骤

1. **确定语义**：明确基础名、元素、最低等级、输入输出类型、容量及是否需要世界 tick。
2. **设计分区**：为每个 IOType 分配连续槽号，并用 `SlotZone` 表达输入/输出职责。
3. **设计面访问**：决定六个世界方向允许看到哪些区域；使用默认访问意味着六面暴露全部标准物品和流体输入/输出。
4. **声明功能族**：在 `ZhenFunctions` 中使用便捷工厂，复杂功能则构造完整 `ZhenFunction`。
5. **接入集中注册**：确保 `ZhenFunctions.register` 调用该功能的 `register`；若其他模块需要最低级类型引用，保存返回的 Supplier。
6. **添加配方数据**：配方类型 ID 必须与展开后的阵类型对应；服务端资源重载负责加载。
7. **补齐资源**：语言、物品模型和必要配方目录应覆盖实际生成的等级集合。
8. **双形态验证**：分别放置独立阵，并把同类型安装到阵总线面，验证二者使用相同分区和配方规则。

## 9. 何时直接注册 ZhenType

`GRID_CELL` 是特殊例子：它有零槽位，业务由 `GridCellSideProcessor` 接管，因此直接注册 `ZhenType`，不通过功能×等级展开。只有满足以下情况才建议这样做：

- 不属于等级功能族；
- 需要专用 SideProcessor；
- 不应自动生成六级变体；
- 生命周期和序列化与普通加工阵显著不同。

直接注册后还要确认是否应生成独立阵方块。当前 `ModBlocks` 会遍历全部 `ZhenType` 条目，因此特殊类型也可能进入自动方块注册集合；扩展者必须明确这是期望行为还是需要过滤。

## 10. 常见问题

- 类型 ID 漏掉 `_zhen`：方块名解析和配方映射可能失效。
- 引入等级写错：会生成不应存在的低级变体，或缺少高级变体资源。
- 区域名不匹配：Capability 存在但暴露空集合。
- 输出槽被当输入槽：Capability 的插入/提取权限由分区语义与面访问共同决定。
- 自定义 tick 绕过回调：存档不标脏、配方缓存不刷新或客户端不更新。
- 只测独立阵：总线使用 `AbstractSideProcessor`，必须验证其序列化和面方向行为。

## 11. 验证清单

- Registry 中每个预期等级都有准确 ID。
- 每个类型都有同名方块、BlockItem 和语言显示。
- 输入变化会使配方重新匹配，空闲时不会每 tick 全量扫描。
- 面 Capability 只能插入输入槽、只能提取输出槽。
- 保存重载后库存、流体和进度可恢复。
- 服务端资源重载后客户端配方展示通过网络同步更新。

## 12. 小结

新增阵的首选路径是声明一个 `ZhenFunction`，让等级系统自动展开 `ZhenType`，再由现有注册、方块实体、IO 和配方系统接管。只有网格单元这类生命周期完全不同的功能才应使用专用类型和处理器。
