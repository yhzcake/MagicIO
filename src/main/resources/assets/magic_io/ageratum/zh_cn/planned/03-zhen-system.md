# 法阵系统

> [!CAUTION]
> **本章全部属于规划内容，尚未实现。** 本章描述目标法阵体验；当前代码中出现同名等级、类型或阵方块，并不表示这里规划的绘制、升级和网络玩法已经完成。

## 1. 法阵结构

规划中的法阵由四类概念组成：

| 部分 | 职责 |
| --- | --- |
| 阵基 | 附着在实体方块表面的滑石阵纹 |
| 阵眼 | 放置引物、激活并进行主要交互的位置 |
| 核心 | 承载等级与元素能力 |
| 附属槽 | 安装速度、效率、产出、容量等升级 |

阵纹不是普通完整方块，而是带有附着面与朝向的表面结构。实现时需要统一坐标变换，使六个面上的绘制、碰撞、渲染和输出方向采用同一套局部坐标规则。

## 2. 绘制流程

1. 玩家主手持滑石，副手放置目标元素引物。
2. 在实体方块表面拖动，形成阵纹轨迹。
3. 系统判断轨迹是否闭合并匹配合法图案。
4. 玩家右键阵眼，消耗引物完成激活。
5. 激活后的法阵获得元素、等级、朝向和可用配方集合。

绘制判定应容许轻微操作误差，但不能仅凭包围盒近似，否则不同图案容易误识别。推荐把轨迹离散到规则网格，再执行旋转、镜像和模板匹配。

## 3. 基础操作

| 操作 | 规划行为 |
| --- | --- |
| 普通右键阵眼 | 激活、打开交互或投入材料 |
| 滑石＋潜行右键 | 旋转输出面 |
| 滑石＋潜行左键 | 移除阵纹并返还部分材料 |
| 手动投料 | LV 阶段主要输入方式 |
| 输出弹出 | LV 阶段主要输出方式 |

所有改变方块状态、库存或掉落物的操作都应由服务端确认；客户端只负责手势预测和视觉反馈。

## 4. 等级序列

| 等级 | 中文名 | 规划特点 | 阵纹视觉 |
| --- | --- | --- | --- |
| LV | 不稳定 | 全手动、基础配方、效率 1 倍 | 暗灰、稀疏粒子 |
| MV | 稳定 | 1 个升级槽、半自动输入输出 | 银白、持续发光 |
| HV | 稳固 | 3 个升级槽、批量处理 | 金色、脉动光环 |
| EV | 充盈 | 4 倍并行、内置过滤 | 彩色、环绕光环 |
| IV | 古朴 | 确定性加工、复杂配方链 | 深紫金边、双重旋转环 |

升级路线计划为：不稳定阵使用稳定引物升至稳定阵，随后依次使用强化引物、充盈引物和古朴引物。升级应保留合法库存与朝向；若新等级容量发生变化，必须先验证能否无损迁移。

## 5. 配方执行

法阵配方需要表达输入物品、输入流体、输出、处理时间、阵能消耗、元素功能、最低等级以及概率产物。高等级法阵向下兼容低等级配方，并可通过等级差获得提速。

一次执行建议遵循：

1. 匹配当前等级和元素允许的配方。
2. 模拟提取全部输入，确保事务可完成。
3. 检查输出空间与能量供给。
4. 锁定配方并推进加工进度。
5. 完成时以事务方式消耗输入并生成输出。
6. 若输出被阻塞，则保留完成状态而不是丢弃产物。

## 6. 复合法阵发现

基础元素通过组合发现后续元素：土与水导向木，水与风导向冰，火与土导向金，风与火导向雷。MV 元素进一步组合为秩序、混沌、空间和时间，终局再组合为描述、能量、意识与创造。

“发现”应是玩家知识进度，而不只是隐藏配方。服务端需要记录发现状态，客户端据此显示教程、配方和图案，避免玩家通过查看数据文件直接跳过探索环节。

## 7. 尺寸与附着

规划视觉尺寸从 LV 的 1×1，发展到 MV/HV 的 2×2 和 EV/IV 的 3×3。尺寸扩大后会涉及跨方块结构、区块边界、任意表面朝向以及结构部分被破坏等问题。主控位置应唯一，附属位置只保存到主控的引用，避免多个方块实体重复执行同一配方。

## 8. 失败反馈

- 图案不完整：高亮缺失或错误节点。
- 引物不符：显示所需元素，不消耗现有物品。
- 等级不足：显示最低阵等级。
- 能量不足：暂停进度并保留已投入材料。
- 输出堵塞：停止新配方，保留待输出结果。
- 结构损坏：立即停止工作，修复后重新校验。
